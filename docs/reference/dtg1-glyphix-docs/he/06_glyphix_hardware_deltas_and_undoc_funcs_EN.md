# מפרט טכני: מאפיינים ומגבלות של פלטפורמת DT NO.1 G1 (ATS3085S / Glyphix OS)

במהלך הנדסה לאחור ובדיקות שטח זוהו המגבלות הקריטיות הבאות של סביבת הריצה (JS Sandbox) במכשיר האמיתי:

## 1. צינור הגרפיקה ו-Layout Engine
* **היעדר Canvas API:** הרכיב `<canvas>` והמתודות של ההקשר (context) שלו הוסרו ברמת החומרה בידי היצרן (Opaque Pointer Trap: `TypeError: not a function`). כל העיבוד הגרפי המותאם חייב להתבצע דרך עץ ה-DOM (הרבה אלמנטי `<div>` קטנים).
* **מגבלות Flexbox ו-CSS:** * מנתח הסגנונות מתעלם מהערך `relative` של המאפיין `position`. יש לבנות מכולות שורש בלעדיו.
  * מיקום מוחלט של צמתי בן נמדד אך ורק מהפינה השמאלית העליונה של המסך `(0, 0)`.
  * המאפיין `transform: rotate()` **אינו נתמך** בחומרה האמיתית (גורם ל-`WARN: unknown style property` ומתעלמים ממנו). סיבוב אלמנטים חייב להיות מחושב מתמטית דרך `left`/`top`.
  * קישור דינמי של מחלקות CSS (classes) אינו נתמך.
* **גיאומטריית התצוגה:** המסך עגול פיזית ברזולוציה של $466 \times 466$ פיקסלים.
  * **אזורים בטוחים (Safe Areas):** אלמנטי טקסט ורכיבי UI חייבים להיות ממוקמים על ציר Y בטווח `45px` (למעלה) - `360px..370px` (למטה), כדי לא להיחתך בידי המסגרת (bezel).

## 2. מערכת הקבצים (VFS) ואחסון (KV)
* **נקודות עיגון (גישת RW):** לאפליקציה גישת קריאה וכתיבה מלאה לשלוש תיקיות:
  * `internal://mass/` - זיכרון משותף. ממופה פיזית אל `/1:/data/mass/` בשעון (נגיש דרך USB מהמחשב).
  * `internal://files/` - זיכרון פרטי של האפליקציה.
  * `internal://cache/` - מטמון פרטי של האפליקציה.
* **מיקום באמולטור במחשב:** מערכת הקבצים הווירטואלית של האמולטור ממופה אל תיקיית הפרויקט: `.glyphix-work\image\default-watch-466x466\data\`.
* **חריגות ב-API של `@system.file` (הבדלים מתקן QuickApp):** * המתודה `file.readText()` בשעון מחזירה **מחרוזת ישירות** (בלי העטיפה `{ text: "..." }`).
  * המתודה `file.list()` מחזירה **מערך שטוח של מחרוזות** עם שמות קבצים (למשל `["test.txt", "purrgo.gpx"]`), ולא מערך אובייקטים `{ uri, length }`. בקושחה הנוכחית אי אפשר לקבל גודל קובץ דרך `list()`.
* **חריגות FlashDB (`@system.storage`):**
  * המתודה `storage.delete(key)` מקבלת **מחרוזת ישירות**, ולא אובייקט `{ key: "..." }` כמו בתקן. העברת אובייקט גורמת לניסיון למחוק את מפתח-המחרוזת `"[object Object]"` ואינה מנקה את הזיכרון האמיתי, וגורמת לדליפות ולכשלי קריאה.
  * בעת בקשת מפתח שאינו קיים, ה-API מחזיר לפעמים את המחרוזת `"undefined"` במקום הטיפוס `undefined`. חובה להשתמש בהמרת טיפוס מפורשת ובבדיקות `String(val) !== 'undefined'`.

## 3. זמן מעבד ו-Watchdog
* **Watchdog אגרסיבי:** למיקרו-בקר אין ריבוי משימות אמיתי. חסימת התהליכון הראשי בחישובים כבדים (למשל ניתוח RegExp של מחרוזות XML/GPX בגודל 5-10 KB בלולאה אחת) גורמת לקיפאון המכשיר.
* **השהיות אסינכרוניות:** כל חישוב אצווה חייב להיעטף בכוח במשימות מאקרו (למשל `setTimeout(..., 50)`), כדי להחזיר זמן מעבד למערכת ההפעלה לטיפול בהפסקות חומרה.

## 4. חיישנים ו-Throttling
* **סערת אירועים (Event Storm):** מודול המצפן החומרתי (`@system.compass`) מייצר הפסקות בתדר של עד 50 Hz.
* **מגבלות תגובתיות:** מנוע הקישור הריאקטיבי של נתונים ב-Glyphix אינו מסוגל לחשב מחדש עשרות סגנונות inline מסוג `left`/`top` בתדר גבוה. אסור להכניס מזהי מנויי חיישנים (`subscribeId`) לאובייקט הריאקטיבי `data: {}`.
* **Throttling (דילול):** יש להגביל בהחלט את ציור ה-DOM מחדש ל-5-10 פריימים בשנייה (דרך דגלי נעילה ו-`setTimeout` של 100-200 ms), אחרת מובטחים התחממות יתר, התרוקנות סוללה וקיפאון הממשק.
* **חריגה בחתימות C++:** * `compass.subscribe()` מקבל **פונקציה ישירות**: `((data) => {})`. העברת אובייקט גורמת לקריסה `InternalError: first args must is a function`. הכיוון (`direction`) מגיע ב-**רדיאנים**.

## 5. מיקום גיאוגרפי (`@system.geolocation`) ומגבלות חומרה של GNSS
* **היעדר תמיכה ב-Promise:** בפלטפורמת ATS3085S המתודה `geolocation.getLocation()` **אינה מחזירה Promise**. חובה להעביר אובייקט עם קולבקים `success` ו-`fail`. ניסיון קריאה דרך `await getLocation()` יחזיר `undefined`.
* **מבנה Payload שונה:** בקולבק `success(data)` קואורדינטות היעד אינן בשורש התשובה אלא באובייקט מקונן `data` (כלומר `data.data.latitude` / `data.data.longitude`).
* **בידוד ה-GNSS המובנה (תחליף Tethered):** בקושחה הסדרתית מודול ה-JS `@system.geolocation` מנותק ברמת החומרה מהשבב המובנה. 
  * המתודה פונה אך ורק לגשר ה-Bluetooth ודורשת חיבור פעיל לאפליקציית הלוואי בסמארטפון.
  * ללא גשר BT פעיל הפונקציה דוחה מיידית את הקריאה דרך הקולבק `fail` עם השגיאה `Code: 1002` ("Currently not connected to the mobile phone Bluetooth network").
  * מתודת הסקירה הרציפה `geolocation.subscribe()` גם היא אינה פועלת באופן עצמאי ו"שותקת באטימות" (אינה קוראת לקולבקים) אם הטלפון אינו מחובר.
  * **גישה ישירה לשבב ה-GNSS של השעון במצב עצמאי אפשרית אך ורק על ידי יצירת Native Applet בשפת C++** דרך ממשק ה-HAL הפנימי של מערכת ההפעלה. או לחלופין אפשר לטלא את הקושחה כדי להפנות את בקשת המיקום אל שבב ה-GNSS המובנה של השעון.
  * באמולטור אין GNSS כלל ו-getLocation() מחזירה תמיד שגיאה. אם נדרש ניפוי שגיאות, יש לזהות שמריצים באמולטור ולבצע mock לנתונים.
  
## 6. עבודה ברקע, מתזמן משימות וניהול זיכרון (OOM Killer)
* **OOM Killer אגרסיבי (Watchdog):** בשעון האמיתי **אין מושג של "עבודה ברקע בזיכרון RAM"**. בדיוק שנייה אחת אחרי כיבוי התצוגה (`onHide`) מערכת ההפעלה הורגת בכוח ובאכזריות את הקשר ה-JS של האפליקציה כדי לשחרר RAM. כל המשתנים הגלובליים, המערכים (`this`) וגם הטיימרים (`setTimeout`/`setInterval`) נהרסים באופן בלתי הפיך.
* **"תחייה חסרת מצב" (Stateless Resurrection):** מתזמן המערכת `@system.schedule` פועל ברמת ליבת מערכת ההפעלה (C++) ו**שורד** את פריקת הקשר ה-JS. כשמגיע מרווח הלוח הזמנים, מערכת ההפעלה מאתחלת את מנוע ה-JS מחדש (מעירה את התהליך משינה עמוקה), קוראת ל-`onCreate`, ומיד לאחר מכן מפעילה את קולבק הטריגר של המתזמן (למשל `onLocationTick`).
* **Deep Sleep וזמני קצוב של החומרה:** כשהמסך כבוי המעבד נכנס לשינה עמוקה. במהלך יקיצה קצרה (ברקע) בידי המתזמן, לחומרה ולמודולי הרדיו אין מספיק זמן ל"הפעלה קרה". לכן בקשות ברקע עלולות להיכשל בגלל זמני קצוב של החומרה (כמו `code: 1002` אחרי 10 שניות).
* **תבנית ארכיטקטונית "Stateless Tracker":**
  1. האפליקציה חייבת להישען לחלוטין על זיכרון לא נדיף (`@system.storage` או `@system.file`) כדי לשמור נקודות ביניים (Waypoints), מצב המעקב (tracker) ומזהים (Job ID).
  2. **בשום פנים ואופן אסור** לבטל את המשימה `schedule.scheduleJob()` (לא לקרוא ל-`cancel`) במתודה `onDestroy`, אחרת מחזור ה"תחייה" ברקע יופסק לנצח.
  3. ב-`onShow` יש לבדוק אם קיימת משימה פעילה ב-`@system.storage`, כדי לא ליצור כפילויות של המתזמן אחרי שהאפליקציה נהרגה והופעלה שוב בידי המשתמש.
  
## 7. התראות מערכת (`@system.notification`)
* **קיצוץ אגרסיבי בידי ה-OEM launcher (DT NO.1):** בשעון האמיתי מרכז ההתראות (המסך הנפתח) ממומש בצורה פרימיטיבית ביותר ומתעלם מרוב המפרט של Glyphix:
  * השדה `icon` מתעלמים ממנו. אייקונים מותאמים של אפליקציות אינם מוצגים בהתראות.
  * השדה `actionUri` (מעברי deep-link) חסום לחלוטין. לחיצה על התראה אינה יכולה להפעיל או להרחיב את אפליקציית המקור, למשתמש זמינה רק מחיקת ההתראה (החלקה הצידה או לחיצה על ה"פח"). ההתראות הן פסיביות (אינפורמטיביות) בלבד.
* **ליקויי האמולטור במחשב:** באמולטור הרשמי המתודה `notification.remove()` אינה ממומשת (גורמת ל-Warning: `remove notification is not implemented yet`). בשעון האמיתי, לעומת זאת, מחיקה או דריסה של התראות לפי `id` קבוע אינה גורמת ל-Warning.

# Glyphix OS: מפרט ופרופיילינג של Canvas API
**סטטוס:** אומת עובדתית באמולטור, במכשיר האמיתי נדרשת בדיקה נוספת

---

## 1. מאפייני מערכת של Canvas API
1. **אתחול:** מבוצע בקריאה למתודה `getContext('2d')` (או `getContext()`) של אלמנט `<canvas>` נייטיב בשלב מחזור החיים `onReady`.
2. **מנגנון Opaque Pointer (C++ Proxy):** אובייקט ההקשר הוא עטיפת פרוקסי מעל צינור הגרפיקה הנייטיבי ב-C++.
3. **הסכנה בבדיקות `if (ctx.method)`:** ניסיון לבדוק קיום מתודה לפני הקריאה מחזיר תמיד `true` (פונקציית העטיפה). קריאה למתודה שלא מומשה ב-C++ גורמת לחריגה קטלנית `TypeError: not a function` ולקריסת הקשר ה-JS. מותר לקרוא **אך ורק** לרשימת הפונקציות שאומתה.

---

## 2. מטריצת התמיכה הסופית ב-API

### 2.1. מתודות ומאפיינים נתמכים

| קטגוריה | ישויות נתמכות | שימוש|
| :--- | :--- | :--- |
| **מאפייני סגנון** | `fillStyle`, `strokeStyle`, `lineWidth` | שליטה בצבע המסלול, הסמן והטקסט ובעובי הקווים |
| **צורות בסיס** | `fillRect`, `strokeRect`, `rect`, `fill` | ניקוי הפריים (`fillRect`), ציור לוחיות ורקעים |
| **קווי מתאר (Path)** | `beginPath`, `moveTo`, `lineTo`, `stroke` | ציור קו המסלול (Polyline) ווקטורי הסמן |
| **עקומות** | `arc`, `arcTo`, `bezierCurveTo`, `quadraticCurveTo` | ציור סמני POI (`arc`), עיגולים וסקאלת המצפן |
| **טרנספורמציות** | `save`, `restore`, `translate`, `rotate`, `scale` | סיבוב והזזה חומרתיים של הקנבס בהתאם לאזימוט התנועה |
| **טקסט** | `fillText` | רינדור ישיר של מרחק, מהירות ורמזים על ה-Canvas |

### 2.2. מתודות חסרות

| מתודה חסרה | סיבה / חלופה (Fallback) |
| :--- | :--- |
| `clearRect` | **קריטי.** מוחלף במילוי בצבע הרקע: `ctx.fillRect(0, 0, width, height)` |
| `ellipse` | מדומה דרך `arc()` |
| `transform` | להשתמש בשילוב של `translate()` ו-`rotate()` |
| `strokeText`, `measureText` | להשתמש רק ב-`fillText()`. את יישור הטקסט לקבוע בהיסטים קבועים |
| `getImageData`, `putImageData` | עבודה ישירה עם מאגר הפיקסלים ב-JS אינה זמינה |
| `clip` | מיסוך באמצעות חיתוך אינו זמין |
| `createLinearGradient` | גרדיאנטים אינם נתמכים. להשתמש בצבע אחיד (`fillStyle`) |

---

## 3. יתרונות ארכיטקטוניים של ה-API המאומת

1. **טרנספורמציות חומרתיות (`rotate` / `translate` / `save` / `restore`):**
   קיום המתודות הללו מאפשר לוותר לחלוטין על טריגונומטריה ידנית של סיבוב וקטורים ב-JS (`Math.cos`/`Math.sin`). מספיק להזיז את מערכת הקואורדינטות למרכז המסך דרך `translate(cx, cy)` ולסובב בזווית האזימוט `rotate(heading)`.

2. **ציור עקומות (`arc` / `arcTo`):**
   מאפשר לרנדר סמנים עגולים של המיקום הנוכחי, נקודות ביניים (Waypoints), וכן רכיבי ממשק (סקאלת מצפן, מד מהירות).

3. **רינדור טקסט ישיר (`fillText`):**
   מבטל את הצורך לבנות שכבות-על מתגיות Flexbox מסוג `<text>` מעל ה-`<canvas>`, מקטין את מספר הצמתים בעץ האלמנטים ומפחית את צריכת ה-RAM של ה-MCU.

---

## 4. תבנית קנונית לניקוי וציור פריים

```javascript
renderFrame() {
  // 1. Clear the screen (Replacement for the missing clearRect)
  this.ctx.fillStyle = '#000000';
  this.ctx.fillRect(0, 0, 466, 466);

  // 2. Save the state of the transformation matrix
  this.ctx.save();

  // 3. Shift the coordinate origin and rotate the canvas to the azimuth (Heading)
  this.ctx.translate(233, 233);
  this.ctx.rotate(this.userHeading);

  // 4. Draw objects (cursor/track) relative to the new center
  // ...

  // 5. Restore the original state of the matrix
  this.ctx.restore();

  // 6. Output static telemetry on top of the frame
  this.ctx.fillStyle = '#00ff00';
  this.ctx.fillText('150m', 200, 420);
}
```
